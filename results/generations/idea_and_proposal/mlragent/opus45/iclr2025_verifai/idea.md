# Title: Specification Inference from Natural Language for LLM Code Generation Verification

## Motivation
A critical gap exists in verifying LLM-generated code: while formal verification tools require precise specifications, users typically describe their intent in ambiguous natural language. Currently, humans must manually translate requirements into formal specifications—a bottleneck that limits practical adoption of verification for AI-generated code. This disconnect means most LLM-generated code goes unverified, creating safety risks in deployment.

## Main Idea
I propose a two-stage framework where a first LLM translates natural language requirements into formal specifications (pre/post-conditions, invariants), which then guide and verify code generated by a second LLM. The key innovation is a **consistency-checking loop**: the generated specifications are validated against the natural language intent using multiple diverse LLM-generated test scenarios, and the generated code is verified against the specifications using SMT solvers.

The methodology involves:
1. Fine-tuning an LLM on paired (natural language, formal specification) datasets from verified codebases
2. Using ensemble disagreement among multiple specification candidates to identify ambiguities requiring user clarification
3. Employing lightweight symbolic execution to check specification satisfiability before code generation

Expected outcomes include higher rates of formally verified LLM-generated code and automatic detection of requirement ambiguities. This bridges the accessibility gap between informal user intent and formal verification, making correctness guarantees practical for everyday LLM code generation.
