# Title
Entropy-Calibrated Conformal Prediction for Uncertainty Quantification in Auto-Regressive LLM Generation

# Motivation
Current conformal prediction methods for LLMs (like COPU) assume i.i.d. calibration sets and use static nonconformity measures, failing to handle auto-regressive dependencies in text generation. This limits reliable uncertainty quantification for deployed LLM systems. Existing approaches either require model internals access or provide no coverage guarantees for sequential generation. We need black-box statistical methods that provide valid uncertainty bounds for production LLM APIs while accounting for sequential dependencies.

# Main Idea
We propose Entropy-Calibrated Conformal Prediction (ECCP), which uses sequential Shannon entropy accumulation as a nonconformity measure under exchangeability assumptions (weaker than i.i.d.). The core mechanism: (1) compute token-wise entropy H(p_t) at each generation step, (2) accumulate entropy along generation paths S(y) = Σ_t H(p_t), (3) calibrate threshold τ via validation set quantiles, (4) construct prediction sets C(x) = {y: S(y) ≤ τ}. This naturally captures generation uncertainty while maintaining O(n) computational complexity. We test on 1000+ samples across summarization, translation, and QA tasks, predicting 90%±2% coverage with ≤10 candidate outputs. The approach requires only token probabilities from LLM APIs, enabling practical deployment with formal coverage guarantees.

### 1.4 Key Assumptions

**A1. Exchangeability (CRITICAL):**
- **Statement:** Calibration and test generation sequences are exchangeable (joint distribution invariant to permutation)
- **Justification:** Weaker than i.i.d.; satisfied when LLM deployment scenarios sample from same underlying task distribution
- **Evidence:** Classical CP theory (Vovk 1999) requires only exchangeability, not i.i.d.
- **Testability:** Empirically verify via permutation tests on calibration set
- **Violation Consequences:** Coverage guarantees void; method degrades to heuristic UQ
- **Mitigation:** Stratified calibration by prompt type/domain to maintain exchangeability within strata

**A2. Token Probability Accessibility (IMPLEMENTATION):**
- **Statement:** LLM API provides token-level probability distributions p_t(x) for entropy computation
- **Justification:** Required for Shannon entropy H(p_t) calculation
- **Evidence:** Most research APIs (OpenAI, Anthropic) provide logprobs; production APIs vary
- **Testability:** Check API documentation for logprobs/token probability support
- **Violation Consequences:** Method inapplicable to black-box APIs without probability access
- **Mitigation:** Fallback to CPQ's query-only approach (missing mass estimators) when probabilities unavailable

**A3. Sequential Entropy Monotonicity (THEORETICAL):**
- **Statement:** Cumulative entropy S(y_{1:t}) is non-decreasing in generation step t
- **Justification:** Each token adds non-negative entropy contribution H(p_t) ≥ 0
- **Evidence:** Shannon entropy H(p) ≥ 0 by definition; equality only for deterministic distribution
- **Testability:** Empirically verify on LLM generation samples
- **Violation Consequences:** Cumulative scoring invalid; requires alternative accumulation scheme
- **Mitigation:** Use absolute value or bounded entropy variants if monotonicity violated

**A4. Calibration Set Representativeness (PRACTICAL):**
- **Statement:** Validation paths drawn from same distribution as deployment scenarios
- **Justification:** CP coverage guarantee assumes calibration and test sets are exchangeable
- **Evidence:** Standard ML assumption; violated under distribution shift (acknowledged in Phase 2A discussion)
- **Testability:** Domain similarity metrics, KL divergence between calibration and test distributions
- **Violation Consequences:** Coverage degradation proportional to distribution shift magnitude
- **Mitigation:** Recalibrate periodically in deployment; use domain adaptation if shift detected
