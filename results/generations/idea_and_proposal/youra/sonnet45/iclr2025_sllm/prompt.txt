# Title
Feature-Guided Routing in Mixture-of-Experts via Sparse Autoencoders for Interpretable Expert Specialization

# Motivation
Large language models with Mixture-of-Experts (MoE) architectures achieve efficiency through sparse expert activation, but routing decisions remain opaque black boxes. This limits trust, debugging, and scientific understanding of expert specialization. Existing interpretability methods analyze models post-hoc, while routing mechanisms optimize only for task performance. We address this gap by integrating sparse autoencoder (SAE) features directly into routing decisions, creating interpretable expert assignments without sacrificing performance.

# Main Idea
We propose co-training SAEs with MoE layers using a learned feature-expert affinity matrix that maps interpretable sparse features to expert selection scores. The causal mechanism operates through three steps: (1) SAE TopK sparsity extracts salient interpretable features from activations, (2) these features multiply with the affinity matrix to generate expert scores, and (3) dual-objective training (reconstruction + routing alignment + task loss) with loss-free expert bias ensures both interpretability and load balance. We test this on transformer LLMs by measuring whether feature-guided routing achieves ≥95% of learned routing performance while providing interpretable expert assignments (Jaccard similarity ≥0.6, human ratings ≥3.5/5). Falsification occurs if performance drops below 90% or feature-expert mappings become arbitrary (Jaccard <0.3). This bridges sparsity-for-efficiency and sparsity-for-interpretability, enabling transparent expert specialization analysis.

**Main Hypothesis:**
In transformer-based LLMs with MoE layers under sparse activation patterns, if SAE features guide routing decisions through a learned feature-expert affinity matrix with dual-objective training (L_total = α·L_reconstruction + β·L_routing_alignment + γ·L_task), then expert assignments become interpretable while maintaining ≥95% of learned routing performance because co-trained features create explicit mappings between interpretable concepts and expert specializations.

**Alternative Hypothesis (H0):**
There is no significant relationship between SAE feature-guided routing and interpretability improvements, OR feature-based routing performs worse than learned routing (<95% performance parity).

### 1.2 Variables

| Variable | Type | Operationalization | Expected Range/Values |
|----------|------|-------------------|----------------------|
| SAE TopK threshold (k) | Independent | Number of active sparse features (k=64) extracted from input activations via SAE encoder | k ∈ {16, 32, 64, 128} (typical range) |

| Affinity matrix size (K×E) | Controlled | Feature dimension K (32,768 for k=64 TopK with 512-dim SAE) × Expert count E | K=32K, E∈{8, 16, 32, 64} (typical MoE configurations) |

### 1.3 Causal Mechanism

**3-Step Causal Chain:**

1. **SAE TopK Activation → Sparse Interpretable Features**
   - Mechanism: TopK sparsity (k=64) enforces selection of most salient activation dimensions, producing sparse feature vectors
   - Falsification: If TopK threshold too low (k<16), insufficient feature diversity; if too high (k>128), noise dominates signal

2. **Sparse Features × Affinity Matrix → Expert Selection Scores**
   - Mechanism: Feature-Expert Affinity Matrix (K×E, learned via cross-reconstruction loss) encodes feature-expert specialization mappings; matrix multiplication produces routing scores
   - Falsification: If affinity matrix learns arbitrary mappings unrelated to semantic content (overfitting to routing shortcuts), feature-expert Jaccard similarity <0.3 or expert specialization collapses (Gini→1)

3. **Expert Selection Scores + Loss-Free Bias → Final Routing + Interpretability**
   - Mechanism: Dual-objective training (L_total = α·L_reconstruction + β·L_routing_alignment + γ·L_task) ensures features optimize for both reconstruction and routing; expert-wise bias maintains load balance without gradient interference
   - Falsification: If loss weights misaligned (β too low→ignores routing, β too high→sacrifices reconstruction), performance <95% of learned routing OR reconstruction loss >1.5× SAE-only baseline

**Evidence for Causal Links:**

| Link | Evidence Source | Key Finding | Strength |
|------|-----------------|-------------|----------|
| Step1 → Step2 | SAEBench (2025, 56 cit) | Feature disentanglement improves with sparsity; Matryoshka SAEs outperform on disentanglement metrics despite lower proxy scores | Strong |
| Step2 → Step3 | SPARC (2025, 1 cit) | Cross-reconstruction loss creates aligned concept spaces (Jaccard 0.80); Global TopK ensures identical latent dimensions activate for given concepts | Medium (novel adaptation to routing) |
| Step3 → Outcome | Loss-Free Balancing (2024, 109 cit) | Expert-wise bias achieves better performance AND load balance without gradient interference from auxiliary loss | Strong |

**Key Tension:**
- **Tension**: SPARC's cross-reconstruction loss was designed for post-hoc model alignment (static analysis), but this hypothesis proposes adapting it for online routing optimization (dynamic training)
- **Resolution**: This verification plan includes staged training protocol (Step 1: pre-train SAE frozen, Step 2: train MoE frozen SAE, Step 3: joint fine-tuning) and explicit dual-objective validation (L_routing_alignment term) to test whether cross-reconstruction principles transfer to dynamic routing context

   - **Consequence if violated**: Experts fail to specialize OR load balance collapses → Gini coefficient <0.3 (under-utilized experts) or >0.7 (overloaded experts)

### 1.5 Scope & Boundaries

**Where Hypothesis Applies:**
- Transformer-based Large Language Models (GPT, Llama architecture families)
- Sparse MoE layers (e.g., Mixtral 8×7B, GPT-4 style architectures)
- Models with sufficient expert specialization (experts learn distinct capabilities)
- Domains where interpretability is valuable (AI safety, scientific discovery, regulatory compliance)

**Where Hypothesis Does NOT Apply:**
- Dense routing mechanisms (no sparse expert selection)
- Non-transformer architectures (CNNs, RNNs lacking MoE layers)
- Homogeneous expert ensembles (all experts identical → no specialization to interpret)
- Extremely small models (<1B parameters) where MoE overhead may dominate benefits

**Known Limitations:**

3. **Hardware Requirements**: Affinity matrix adds ~8MB memory overhead; Triton kernel optimization needed for competitive inference speed
4. **Expert Count Dependency**: Effectiveness may degrade with very large expert counts (E>64) due to affinity matrix size scaling
