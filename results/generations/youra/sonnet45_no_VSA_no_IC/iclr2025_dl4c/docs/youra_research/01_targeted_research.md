### Extracted Technical Terms
- **Execution Feedback:** Test pass/fail signals, error messages, stack traces from program execution
- **Actor-Critic RL:** Code generator (actor) + correctness predictor (critic) training framework
- **Critical Sampling:** Inference-time regeneration based on critic scores and test feedback

- **Test Insufficiency:** Gap between limited test coverage and true functional correctness

### Research Context
All 6 reference papers converge on execution-based evaluation and feedback for code generation, with three distinct approaches:

1. **RL-Based Alignment (CodeRL):** Uses test outcomes as RL reward signal for training - heavy infrastructure but proven effective
2. **Self-Correction (Self-Debug):** Lightweight feedback loop with NO external critic - aligns with stability-first design
3. **Rigorous Evaluation (EvalPlus):** Exposes hidden failures through comprehensive testing - motivates execution feedback necessity

**Key Insight for Research Question:** Papers #2 (Self-Debug) and #5 (EvalPlus) directly support lightweight execution feedback WITHOUT complex LLM gating. Paper #1 (CodeRL) shows RL viability but introduces instability risk. Papers #3-4 provide existing benchmarks (HumanEval, MBPP, APPS) with test suites - no new data needed.

**Avoiding Previous Failure:** Self-Debug approach (Paper #2) uses simple execution results + explanation, NOT heavy critic networks (CodeRL) or LLM filtering (EVAF). This removes infrastructure instability from critical path.

## 1. Research Questions

### Primary Research Question
Can lightweight execution feedback signals (test outcomes, error messages) from existing benchmarks (HumanEval, MBPP) reliably improve code generation model alignment using fault-tolerant, checkpointed training infrastructure?

### Detailed Research Questions
1. What is the empirical performance gain from training on raw test pass/fail + error messages vs supervised fine-tuning on existing benchmarks?
2. Does checkpointed execution feedback collection with per-problem timeouts achieve >95% completion rate on HumanEval/MBPP full suites?
3. Which execution feedback components (test pass/fail, error type, stack trace) provide strongest alignment signal?
4. Does alignment on HumanEval execution feedback transfer to MBPP performance improvements without additional training?

### Lessons from Previous Attempts (ROUTE_TO_0)

**Previous Failure: H-E1 (EVAF Existence PoC)**

**What Was Tried:**
- Hypothesis: EVAF mechanism can be implemented and produces filtered AI feedback with measurable accept rate between 20-60%
- Experiment crashed at 53% completion (87/164 HumanEval problems) during EVAF gating phase
- Used CodeLlama-7b-Instruct for feedback generation
- No checkpointing in EVAF loop - full restart required on crash

**Why It Failed:**
1. Model Inference Instability: CodeLlama-7b-Instruct stalled on complex HumanEval problems
2. Resource Management: GPU memory exhaustion (CodeLlama-7b requires ~14GB VRAM)
3. No Fault Tolerance: Single-run design with no progress checkpointing
4. Scale Mismatch: Full 164-problem suite too large for unstable inference pipeline

**Root Cause:** Infrastructure stability issues, not hypothesis validity. EVAF concept unvalidated due to execution failures.

**How THIS Direction Avoids Those Pitfalls:**
- **Smaller Models**: Focus on feedback extraction using <1B models (stable, low VRAM)
- **Checkpointed Execution**: Progress saved every N problems, graceful recovery from failures
- **Reduced Initial Scope**: PoC on 50-problem subset before scaling
- **Execution-Only Feedback**: Use raw test outcomes/error messages (no LLM gating in critical path)
- **Timeout Protection**: Per-problem time limits with skip-on-timeout logic

**Key Insight:** Previous attempt conflated two research questions:
1. Can execution feedback improve code LLMs? (core question)
2. Can LLM-gated feedback filtering work at scale? (EVAF-specific)

**New Strategy:** Validate Q1 first with simple execution feedback (test pass/fail + error messages). Only explore Q2 (LLM gating) after stable infrastructure proven.

### Code Examples Found

**[INFERRED]** Example 1: Execution Feedback Loop (Pseudocode)
- Source: General knowledge (Archon search unavailable)
- Reasoning: Standard pattern for test-driven code generation
```python
# Lightweight execution feedback loop (no LLM gating)
def align_with_execution_feedback(model, problems, checkpoint_every=10):
    checkpoint = load_checkpoint()  # Resume support
    results = checkpoint.get('results', [])
    
    for idx, problem in enumerate(problems[len(results):]):
        try:
            # Generate code with timeout protection
            code = model.generate(problem.description, timeout=60)
            
            # Execute tests with timeout
            test_result = run_tests(code, problem.tests, timeout=30)
            
            # Simple feedback: pass/fail + error messages (no LLM gating)
            feedback = {
                'passed': test_result.passed,
                'errors': test_result.errors if not test_result.passed else None
            }
            
            results.append({'problem': idx, 'code': code, 'feedback': feedback})
            
            # Checkpoint every N problems (EVAF lacked this)
            if (idx + 1) % checkpoint_every == 0:
                save_checkpoint({'results': results, 'idx': idx})
                
        except TimeoutError:
            # Skip problematic inputs instead of crashing (EVAF lacked this)
            results.append({'problem': idx, 'code': None, 'feedback': 'TIMEOUT'})
            continue
    
    return results
```
- Relevance: Addresses EVAF failure modes (checkpointing, timeouts, no heavy LLM critic)

## 8. Research Gaps

### User Input Recall

**Primary Research Question:** Can lightweight execution feedback signals (test outcomes, error messages) from existing benchmarks (HumanEval, MBPP) reliably improve code generation model alignment using fault-tolerant, checkpointed training infrastructure?

**ROUTE_TO_0 Context:** Previous EVAF attempt failed (53% completion crash) due to CodeLlama-7b instability, no checkpointing, GPU OOM. New direction avoids LLM gating, uses <1B models, checkpointed execution.

### Identified Gaps

#### Gap 1: Optimal Execution Feedback Granularity for Small Models

**Current State:** Multiple papers explore execution feedback (CodeRL+, CoCoS, DebugRepair), but granularity varies: binary pass/fail (CodeRL), variable-level traces (CodeRL+), runtime evidence (DebugRepair). No systematic study on optimal granularity for <1B models.

**Missing Piece:** Empirical comparison of feedback granularity (pass/fail only vs + error messages vs + stack traces vs + variable traces) specifically for lightweight models (<1B params) on HumanEval/MBPP.

**Potential Impact:** Could determine minimal sufficient feedback signal for small model alignment, reducing infrastructure complexity while maintaining effectiveness.
