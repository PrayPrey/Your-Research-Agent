\section{Related Work}

Our work connects to three research threads: model-based code evaluation metrics, LLM-as-judge for code correctness, and ensemble methods for evaluation. We position our contribution as the first scale-controlled analysis of error patterns in LLM code judges.

\subsection{Model-Based Code Evaluation}

Traditional code evaluation relies on execution-based metrics such as pass@k \cite{chen2021evaluating}, which measure functional correctness through test execution. While rigorous, execution requires infrastructure and compute that scales poorly with evaluation volume.

Model-based alternatives emerged to approximate execution signals. CodeBERTScore \cite{zhou2023codebertscore} computes semantic similarity using code-pretrained embeddings, achieving higher correlation with human preference than BLEU. However, Naik (2024) demonstrates that CodeBERTScore has only \textbf{0.16 correlation} with functional correctness---useful for editing effort prediction (0.72 correlation) but unreliable for correctness judgment.

\subsection{LLM-as-Judge for Code}

\textbf{Bias characterization.} Moon et al. \cite{moon2025biases} identify six bias types in LLM code judges: sensitivity to variable names, comments, formatting, and other superficial features. Our work complements this by showing that bias \textit{magnitude} varies by scale.

\textbf{Accuracy evaluation.} Crupi et al. \cite{crupi2025effectiveness} evaluate eight LLMs as judges on 1,405 Java and 1,281 Python methods, finding GPT-4-turbo performs best but ``frequently misjudges'' correctness. Critically, their study does not control for scale. Our work fills this gap with systematic 7B/70B/proprietary comparison under fixed evaluation settings.

\textbf{Test-time scaling.} Wang et al. \cite{wang2025mctsjudge} introduce MCTS-Judge, applying System-2 thinking to improve single-model accuracy from 41\% to 80\%. Our findings are complementary: MCTS-Judge improves a single judge; we show that combining judges across scales without such compute is counterproductive.

\subsection{Ensemble Methods}

Ensemble methods assume component errors are approximately IID. Shu \cite{shu2026blind} demonstrates that LLM judge panels share fundamental error modes even when architecturally diverse. Our findings extend this: within scale-diverse panels, errors are not only correlated but systematically asymmetric, making majority voting actively harmful.
