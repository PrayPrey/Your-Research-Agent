# Discussion

## What This Failure Does NOT Tell Us

The experiment crashed due to infrastructure issues—not because the EVAF mechanism was theoretically flawed. We cannot conclude:

- That EVAF does not work
- That accept rates are outside the viable range
- That execution gating provides no benefit over unfiltered AI feedback
- That the fidelity × richness framework is incorrect

The hypothesis remains **untested**, not refuted. Infrastructure failure is epistemically different from mechanism disproval.

## What This Failure DOES Tell Us

### Infrastructure Requirements

EVAF combines two computationally expensive operations: large model inference (7B parameter CodeLlama) and dynamic code execution. Running these in sequence for 164 problems requires:

1. **Sufficient GPU memory**: 7B models in float16 need ~14GB. Combined with baseline model context and generated sequences, peak memory may exceed typical consumer GPU limits.

2. **Robust error handling**: Code generated by imperfect models may contain pathological patterns (infinite loops, memory bombs) that stress subprocess isolation.

3. **Checkpointing**: Long-running experiments must save intermediate state to allow resume after failure.

Our implementation lacked these safeguards. Future work must address infrastructure before claiming experimental validation.

### Computational Overhead

EVAF is inherently expensive. For each problem, it requires:
- One baseline model inference (CodeT5-770M)
- One feedback model inference (CodeLlama-7b)
- One test execution with subprocess overhead

This is approximately 2x the inference cost of pure execution feedback (which only runs baseline + tests) plus subprocess management overhead. Whether this cost is justified depends on whether verified feedback improves downstream training—a question we cannot answer without completing the experiment.

## Implications for EVAF Theory

The theoretical framework remains plausible. The claim that fidelity and richness are orthogonal dimensions is conceptual, not empirical—it stands regardless of experimental outcome. The claim that execution gating could filter AI suggestions is validated by partial execution: the pipeline successfully ran gating for 87 problems before crashing.

What remains unknown is whether the accept rate falls in the viable 20-60% range and whether filtered feedback improves model learning. These are empirical questions requiring successful experiment completion.

## Comparison to Related Work

Our infrastructure failure parallels challenges reported in related work:

- **RLTF** notes runtime complexity of online RL with unit test execution
- **Self-Refine** reports high compute cost for iterative refinement
- **PPOCoder** uses extensive engineering for stable RL training

Code generation feedback research requires significant infrastructure investment beyond proof-of-concept implementation.

## Limitations

Beyond the obvious incomplete experiment, this work has structural limitations:

1. **Single model pair tested**: Different baseline/feedback model combinations may yield different results. CodeLlama-7b may be too large or too small; CodeT5-770M may not be representative of modern code models.

2. **HumanEval only**: The benchmark is relatively small (164 problems) and may be saturated for frontier models. Results may not generalize to APPS or MBPP.

3. **No training experiments**: Even if accept rate is viable, we have not demonstrated that verified feedback improves model learning.

4. **No baseline comparison**: We have not compared EVAF to Exec-Fine or AI-Only approaches.

## Recommended Next Steps

1. **Immediate**: Add checkpointing to train.py gating loop. Profile GPU memory usage. Consider quantized CodeLlama (4-bit via bitsandbytes).

2. **Short-term**: Complete the existence experiment. Report accept rate. If viable (20-60%), proceed to comparative evaluation.

3. **Medium-term**: Design training experiment comparing EVAF-trained models to Exec-Fine and AI-Only baselines on pass@k metrics.

4. **Long-term**: Investigate accept rate optimization, difficulty stratification, and transfer to other benchmarks.
