\section{Methodology}
\label{sec:methodology}

Our methodology directly tests the independence claim that underlies layered verification pipelines. We use Jaccard indices on improvement sets because this metric directly measures overlap between error classes---if two verification strategies improve largely disjoint sets of problems, they target independent error classes.

\subsection{Error Class Independence Measurement}

\subsubsection{Problem Formulation}

For a code generation benchmark with problems $P = \{p_1, \ldots, p_n\}$, each verification strategy $s$ produces an improvement set $I_s \subseteq P$ containing problems where strategy $s$ increases correctness.

We measure independence between strategies $s_1$ and $s_2$ using the Jaccard index:
\begin{equation}
J(s_1, s_2) = \frac{|I_{s_1} \cap I_{s_2}|}{|I_{s_1} \cup I_{s_2}|}
\end{equation}

\textbf{Interpretation:}
\begin{itemize}
    \item $J = 0$: Complete independence (disjoint improvement sets)
    \item $J = 1$: Complete overlap (identical improvement sets)
    \item $J < 0.30$: Largely independent (our threshold for multiplicative model)
\end{itemize}

\subsubsection{Strategy Definitions}

We define three verification strategies corresponding to different error classes:

\textbf{Grammar Constraints ($s_g$):} Token-level logit masking via deterministic finite automaton (DFA). Uses SynCode~\cite{syncode2024} in \texttt{grammar\_strict} mode with Python grammar. Improvement: problem passes after constrained generation when it failed with unconstrained baseline.

\textbf{Static Analysis ($s_a$):} AST-level pattern matching using Bandit~\cite{bandit2024} (security) and Pylint (reliability). Improvement: code has fewer static analysis issues after feedback-based refinement.

\textbf{SMT Verification ($s_m$):} Formal specification checking using Z3~\cite{z3solver} on HumanEval-Verus~\cite{humaneval_verus2024} problems (23 problems with Verus specifications). Improvement: code satisfies formal specification after SMT-guided repair.

\subsubsection{Evaluation Protocol}

For each strategy pair, we compute:
\begin{enumerate}
    \item Generate baseline code for all problems
    \item Apply each strategy independently
    \item Identify improvement sets $I_{s_g}$, $I_{s_a}$, $I_{s_m}$
    \item Compute pairwise Jaccard indices
\end{enumerate}

We test across two models (CodeLlama-7b-hf, GPT-4) to verify independence holds across capability levels.

\subsection{Pipeline Architecture}

Building on the independence framework, we design a sequential pipeline ordered by abstraction level:

\begin{enumerate}
    \item \textbf{Stage 1: Grammar Constraints} --- Token-level logit masking via DFA. Targets syntax errors (compilation failures).
    \item \textbf{Stage 2: Static Analysis} --- AST-based pattern matching + LLM repair. Targets semantic issues (security, reliability).
    \item \textbf{Stage 3: SMT Verification} --- Z3 constraint solving + guided repair. Targets specification violations.
\end{enumerate}

\textbf{Rationale for ordering:} Lower abstraction levels (syntax) should be resolved before higher levels (semantics, specifications), as syntactically invalid code cannot be meaningfully analyzed for semantic issues.

\subsection{Hypothesis Testing}

We decompose the main hypothesis (multiplicative error reduction) into testable sub-hypotheses:

\textbf{H-E1 (Existence):} Error classes are largely independent (Jaccard $< 0.30$ for all strategy pairs).

\textbf{H-M1 (Mechanism):} Grammar-constrained decoding reduces syntax errors by measurable margin through prefix automata enforcement.

\textbf{H-M2 (Mechanism):} Static analysis feedback reduces semantic issues when using instruction-tuned models.

\textbf{H-M3 (Mechanism):} SMT-guided repair enforces specification satisfaction on semantically-filtered code.

\textbf{H-M4 (Mechanism):} Pipeline composition achieves synergy coefficient $S \geq 0.8$, where:
\begin{equation}
S = \frac{\text{Combined improvement}}{\sum \text{Individual improvements}}
\end{equation}

This decomposition allows partial validation---if one mechanism stage fails, we can identify the specific failure mode rather than rejecting the entire hypothesis.

\subsection{Experimental Design Choices}

\textbf{Jaccard over raw counts:} Raw error counts confound strategy effectiveness with baseline error rates. Jaccard on improvement sets directly measures overlap.

\textbf{Sequential pipeline:} We test the natural ordering (syntax $\rightarrow$ semantics $\rightarrow$ specifications). Alternative orderings could be tested in future work.

\textbf{HumanEval + HumanEval-Verus:} HumanEval (164 problems) enables broad testing; HumanEval-Verus (23 problems with specifications) enables SMT stage evaluation.

\textbf{Two models:} CodeLlama-7b-hf (open-source, 7B parameters) and GPT-4 (frontier, API-based) span the capability spectrum, testing whether independence holds across model sizes.
