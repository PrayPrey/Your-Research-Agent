# Introduction

Current code generation benchmarks measure *whether* agents produce correct code (HumanEval pass@k), but not *how* they debug failing code. An agent may pass 95% of tests through 100 random modifications (inefficient trial-and-error) or through 10 strategic root-cause fixes (efficient debugging) — current metrics cannot distinguish these behaviors. This gap matters: without process metrics, we cannot measure or improve agents' iterative problem-solving ability, limiting progress toward autonomous software development.

Existing benchmarks focus on outcomes — HumanEval and MBPP use pass@k to measure generation success rate ~\cite{Chen2021Evaluating, Austin2021Program}. These metrics suffice for single-attempt correctness but miss debugging efficiency. Multi-test benchmarks like LeetCode and Codeforces provide test suites with 15+ test cases per problem, revealing debugging trajectories invisible to single-attempt evaluation. However, existing work reports final pass rates rather than analyzing *how* tests are passed — whether agents identify root causes and fix multiple failures simultaneously, or address each failure independently through trial-and-error.

The deeper problem is that agentic debugging requires strategic behavior (clustering errors by shared characteristics, prioritizing high-impact fixes) invisible to outcome-only metrics. An agent that clusters three failures sharing "index out of range" errors and fixes all three with one modification exhibits conceptual understanding distinct from an agent that addresses each failure separately. This strategic debugging capability — iterating efficiently through error feedback — is a hallmark of agentic systems, yet existing frameworks provide no metrics to measure it.

We identify a critical gap: no execution-based metrics quantify *how efficiently* agents debug. Competitive programming benchmarks measure total pass rate; HumanEval/MBPP use single-attempt pass@k; SWE-bench evaluates GitHub issue resolution without analyzing debugging trajectories when test suites exist. Without process metrics, we cannot distinguish strategic debugging (conceptual understanding enabling root-cause identification) from sequential trial-and-error (brute-force iteration without pattern recognition).

Our key insight is that strategic debugging operates as a *feedback loop* (error → cluster → prioritize → fix → repeat), not a *learning system* (observe → extract → predict → generalize). We introduce fix-impact-ratio, a metric measuring tests passed per code modification: strategic agents achieve ratio > 2.0 by targeting root causes resolving multiple failures simultaneously, while sequential agents show ratio ≈ 1.0 (one fix per failure). Experiments validate a two-stage mechanism — agents cluster errors by shared characteristics at 2× random rate (coefficient 1.909 vs 0.950, p=0.001), then prioritize fixes yielding 2.15× higher proportion of high-impact modifications (42.5% vs 19.8%). Surprisingly, pattern-based transfer to held-out tests failed (slope ratio 0.82 < threshold 1.5, 0% pattern usage), revealing strategic debugging requires error feedback rather than enabling autonomous prediction.

Building on this insight, we contribute: (1) a fix-impact-ratio framework with three execution-based metrics (fix-impact-ratio for efficiency, clustering coefficient for pattern recognition, held-out slope for generalization), (2) experimental validation demonstrating the two-stage mechanism works with large effect size (Cohen's d=3.07) while transfer learning fails clearly (p=0.504, not significant), and (3) theoretical clarification that strategic debugging is a feedback loop enabling iterative improvement with error messages, not a learning system supporting predictive generalization without test execution. Our framework extends existing correctness benchmarks (HumanEval, MBPP) by measuring debugging *process* alongside *outcomes*, opening evaluation of agentic capabilities beyond pass@k.
