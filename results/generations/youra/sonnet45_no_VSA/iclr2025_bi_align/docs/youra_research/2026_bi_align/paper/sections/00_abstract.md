# Abstract

**For CNN architectures with fixed-length inputs**, we identify a critical timing issue in GPU memory profiling: existing methods measure before the optimizer step, missing peak allocations. Out-of-Memory (OOM) failures waste GPU-hours on failed experiments, yet state-of-the-art profiling achieves only 5.46% median error. We introduce **post-optimizer sampling in iteration 1**—measuring memory immediately after `optimizer.step()` completes—to capture Adam's momentum buffers (approximately 2× parameter memory) that prior iteration-2 sampling delays. Validated on ResNet-18 and ResNet-34 with Adam, AdamW, and SGD optimizers using CIFAR-10-scale synthetic data (4 configurations, statistical significance not established: p=0.0625, n=4), our protocol achieves 2.6% median relative error, representing preliminary evidence of a 52% reduction compared to VeritasEst's cross-architecture baseline (5.46%). All four tested CNN configurations remain below 7% error, with 95th percentile error at 6.1%. We discover optimizer-specific accuracy: Adam achieves 0.00-0.62% error (10× better than SGD's 4.57-6.38%), challenging the assumption that memory profiling is optimizer-agnostic. This work reframes lightweight memory profiling as a timing optimization problem—demonstrating that *when* you measure matters as much as *how many* iterations you profile—while acknowledging that **transformer architectures (0/8 tested), variable-length sequences, real datasets, and batch size scaling remain unvalidated**.
